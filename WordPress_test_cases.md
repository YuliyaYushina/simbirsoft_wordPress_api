   | 2 | Заполнено только поле title | отсутствует | отсутствует | 201 | Тело ответа в формате JSON: значение title.raw соответсвует отправленному значению, в теле ответа присутствует поле id (тип: integer, значение > 0) |
   | 3 | отсутствует | Заполнено только поле content | отсутствует | 201 | Тело ответа в формате JSON: значение content.raw соответсвует отправленному значению, в теле ответа присутствует поле id (тип: integer, значение > 0) |

Тест-кейс № 2 Запрос на создание публикации при пустом теле запроса

Шаги:
1. Сформировать POST запрос /wp/v2/posts.

``` json
  "data": {
    "status": 400
  }

```

Тест-кейс № 3 Успешное изменение существующей публикации

Описание: Проверка получения статуса при успешном изменении существующей публикации в WordPress

Предусловие:
1. Сформировать POST запрос /wp/v2/posts.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. В Body прописать JSON с полями title = "Изменение публикации", content = "Успешное изменение публикации", excerpt = "Изменение публикации".
4. Отправить запрос.
5. Получить HTTP-код: 201 и тело ответа в формате JSON. Сохранить id созданной публикации.

Шаги:
1. Сформировать POST запрос /wp/v2/posts/<id>, где id - сохраненное id созданной публикации.
2.  Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3.  В Body передать JSON
   ```json
   {
   "title":"Поле title изменено"
   }
   ```
4. Отправить запрос.

Ожидаемый результат:
HTTP-код: 200 ОК. Тело ответа в формате JSON: 
- id соответсвует сохраненому id созданной публикации,
- значение title.raw равно "Поле title изменено",
- значение content.raw осталось прежним "Успешное изменение публикации",
- значение excerpt.raw осталось прежним "Изменение публикации".

5. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.

Ожидаемый результат:
HTTP-код: 200 ОК. Тело ответа в формате JSON:
- id соответствует сохраненному id удаленной публикации,
- поле status равно "trash".

Тест-кейс № 5 Удаление уже удаленной публикации

Описание: проверка получения сатуса при попытке удаления уже удаленной публикации.

Предусловие:
1. Сформировать POST запрос /wp/v2/posts.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. В Body прописать JSON с полями title = "Удаление публикации", content = "Успешное удаление публикации", excerpt = "Удаление публикации".
4. Отправить запрос.
5. Получить HTTP-код: 201 и тело ответа в формате JSON. Сохранить id созданной публикации.
6. Сформировать DELETE запрос /wp/v2/posts/<id>, где id - сохраненное id созданной публикации.
7. Отправить запрос.
8. Получить HTTP-код: 200 и тело ответа в формате JSON.

Шаги:
1. Сформировать DELETE запрос /wp/v2/posts/<id>, где id - сохраненное id удаленной публикации.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. Отправить запрос.

Ожидаемый результат:
HTTP-код: 410 Gone.
Тело ответа в формате JSON:
```json
{
  "code": "rest_already_trashed",
  "message": "Запись уже была удалена.",
  "data": {
    "status": 410
  }
}
```

Тест-кейс № 6 Создание комментария к существующей публикации

Описание: проверка получения статуса при успешном создании комментария к существующей публикации

Предусловие:
1. Сформировать POST запрос /wp/v2/posts.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. В Body прописать JSON:
```json
{
"title":"Публикация для проверки создания комментария",
"content":"Успешное создание комментария к публикации",
"excerpt":"Создание комментария",
"status":"publish"
}
```
4. Отправить запрос.
5. Получить HTTP-код: 201 и тело ответа в формате JSON. Сохранить id созданной публикации.

Шаги:
1. Сформировать POST запрос /wp/v2/comments.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. В Body прописать JSON:
   
```json
{
"post":"<id>",
"content":"Успешный комментарий к публикации"
}
```
где id - сохраненный id созданной публикации.

4. Отправить запрос.

Ожидаемый результат:
HTTP-код: 201 Created.
Тело ответа в формате JSON:
- в теле ответа присутствует поле id (тип: integer, значение > 0),
- значение post соответствует отправленному значению,
- значение content.rendered соответствует отправленному значению.

1. Сформировать POST запрос /wp/v2/posts.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.
3. В Body прописать JSON:
```json
{
"title":"Публикация для проверки создания комментария (негативный сценарий)",
"content":"Успешное создание комментария к публикации (негативный сценарий)",
"excerpt":"Создание комментария (негативный сценарий)",
"status":"publish"
}
```
4. Отправить запрос.
5. Получить HTTP-код: 201 и тело ответа в формате JSON. Сохранить id созданной публикации.

1. Сформировать POST запрос /wp/v2/comments.
2. Настроить Authentication: выбрать Basic-Auth, ввести логин и пароль, которые вводились при регистрации в системе.

| 3 | отсутствует | Попытка создать комментарий к публикации | 403 Forbidden | Тело ответа в JSON: ``` {"code": "rest_comment_invalid_post_id", "message": "Извините, вам не разрешено создать этот комментарий без записи.","data": {"status": 403}}``` |
| 4 | один | Попытка создать комментарий к публикации | 400 Bad Request | Тело ответа в JSON: ```{"code": "rest_invalid_param", "message": "Неверный параметр: post", "data": { "status": 400, "params": {"post": "post не принадлежит к типу integer."},"details": {"post": {"code": "rest_invalid_type","message": "post не принадлежит к типу integer.","data": {"param": "post"}}}}}``` |

где id - сохраненный id созданной публикации
